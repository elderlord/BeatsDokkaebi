# 도깨비불 봉인 — 맥놀이 게이미피케이션 전시 콘텐츠 설계

- 작성일: 2026-07-23
- 프로젝트: BeatsDokkaebi
- 성격: 무인 전시용 웹 콘텐츠 (아이패드, 오프라인, 무한 재생)

## 1. 개요

맥놀이(beat) 물리 현상을 "도깨비불 봉인"이라는 컨셉으로 체험시키는 단일 화면
전시 콘텐츠. 관람객이 좌·우 슬라이더로 두 사인파의 주파수를 조절하고, 두
주파수가 가까워지면 실제 맥놀이가 발생한다. 맥놀이가 목표 구간에 유지되면
도깨비불이 봉인된다.

- **핵심 성격: 과학 시연 우선.** 실제 두 사인파를 Web Audio로 재생해 진짜
  맥놀이(wah-wah)를 들려주는 것이 1순위. 도깨비는 현상을 눈으로 보여주는
  시각화 장치.
- **게임 루프: 목표 → 봉인 → 리셋.** 명확한 성취와 자동 초기화가 있는 전시물.
- **봉인 성공 조건: 느린 맥놀이 구간(약 1~6Hz)에 약 3초 유지.**
- **조작 주체: 1인 양손.** 한 사람이 좌·우 슬라이더를 동시에 조작.
- **아트: 절차적 생성(코드).** 외부 이미지 없이 Canvas/CSS 파티클로 도깨비불 생성.
- **기술: 단일 HTML(A안).** Vanilla JS + Web Audio + Canvas, 의존성 0, 오프라인.

## 2. 화면 레이아웃 & 상태 흐름

### 방향/화면
- 아이패드 **가로(landscape)** 고정, 전체화면, 단일 화면.

### 레이아웃
```
┌─────────────────────────────────────────────────────────┐
│                    [ 봉인의 결계 문양 · 배경 ]              │
│   ┌───┐                                          ┌───┐    │
│   │ ▲ │            🔥 도깨비불 (중앙)             │ ▲ │    │
│   │ █ │         (파티클 · 강도에 반응)            │ █ │    │
│   │ ▼ │      봉인 진행 링 (원형 게이지)           │ ▼ │    │
│   └───┘                                          └───┘    │
│  좌 주파수          현재 맥놀이: 4.2 Hz           우 주파수  │
│  438 Hz         "결계가 흔들린다..."             442 Hz   │
└─────────────────────────────────────────────────────────┘
```

- 좌·우 **세로 슬라이더**: 양손 엄지로 잡기 좋은 위치, 큰 히트영역.
- 각 슬라이더 주파수 범위: **380~500 Hz** (중앙 ≈ 440Hz). 절대음이 잘 들리는
  대역이며 두 값이 겹치는 목표 구간을 자연스럽게 만들 수 있음.
- 중앙 **도깨비불** + 둘레의 **봉인 진행 링**(목표 유지 시간을 원형으로 채움).
- 하단에 현재 맥놀이(Hz)와 짧은 상태 문구.

### 상태 흐름 (무한 루프)
```
[ATTRACT 유휴] --터치--> [PLAY 조작] --목표구간 3초 유지--> [SEAL 봉인성공]
     ▲                        |                                    |
     └──── 20초 무입력 ────────┘                                    |
     └──────────────────── 4초 축하 후 자동 초기화 ──────────────────┘
```

- **ATTRACT(유휴)**: 도깨비불이 크게 넘실대며 유도 문구("결계를 흔들어 도깨비를
  봉인하라") + 슬라이더 손짓 힌트. 첫 터치 시 오디오 활성화.
- **PLAY**: 조작 시작. 20초간 입력이 없으면 ATTRACT로 자동 복귀.
- **SEAL**: 목표 맥놀이 구간을 약 3초 연속 유지 시 발동 → 절정 연출 → 봉인 문양
  완성 → 4초 후 초기화.

## 3. 오디오 엔진 (핵심)

Web Audio API로 실제 맥놀이를 물리적으로 생성한다. 가짜 효과음이 아니라 두
사인파의 실제 간섭.

- 두 개의 `OscillatorNode`(좌·우), `type='sine'`. 슬라이더 값 → `frequency`.
  주파수 이동은 `setTargetAtTime`으로 부드럽게(클릭·지직음 방지).
- 신호 경로: `각 oscillator → gain → 합산 → 마스터 gain → 스피커`. 두 파형이
  합쳐지며 진폭이 |f1−f2| 주기로 진동 = 실제 맥놀이.
- **맥놀이 계산**: `beat = |f1 − f2|`. 이 값이 화면 표시·게임 판정·괴로움 강도의
  단일 소스.
- **오디오 시작 정책**: iOS 사파리는 사용자 제스처 이후에만 소리 재생 가능 →
  ATTRACT 화면 첫 터치에서 `AudioContext.resume()`.
- **볼륨 안전장치**: 마스터 게인 상한 고정, 봉인 성공 후 정적 구간에서 페이드아웃.
- 도깨비 신음/비명 레이어는 선택적 추가 사운드로 맥놀이 위에 얹어 distress에 연동
  (절차적 합성 또는 짧은 내장 샘플; 외부 네트워크 의존 없이 인라인).

## 4. '괴로움 강도' 단일 매핑

세 피드백 채널을 하나의 값 `distress ∈ [0,1]`로 묶는다.

```
beat = |f_left − f_right|          // 실제 맥놀이 Hz
목표 구간: 1~6 Hz (여기서 distress 최대)
distress = 1: 목표 구간 정중앙(≈3Hz)
distress → 0: beat가 목표에서 멀어질수록(너무 크거나 0에 붙음)
```

`distress`가 커질수록 동시에:
1. **도깨비불** — 크기↓, 흔들림↑, 색이 파랗게 질리고 깜빡임↑
2. **화면** — 진동(shake)·비네팅·봉인 문양 발광↑
3. **소리** — 도깨비 신음/비명 레이어 볼륨↑ (맥놀이 wah-wah 위에 얹힘)

- **봉인 판정**: `distress`가 임계값 이상으로 **3초 연속 유지** → 진행 링이 다
  차면 SEAL.
- 목표를 벗어나면 진행 링이 서서히 감소(관용시간을 둬서 손떨림 허용).

## 5. 비주얼: 절차적 도깨비불

- `<canvas>` 파티클 시스템: 불꽃 입자를 매 프레임 생성·상승·소멸. 한국 도깨비불
  이미지의 푸른빛/청록 불꽃 + 흔들리는 코어.
- `distress` 바인딩:
  - 평소: 크게 넘실. distress↑: 쪼그라들고 파랗게 질리며 파르르 떨림.
  - 입자 방출량·난류(turbulence)가 distress에 따라 요동.
- **봉인 진행 링**: 도깨비불 둘레 원형 게이지(Canvas/SVG), 목표 유지 시간을 채움.
- **화면 이펙트**: CSS `transform` 기반 shake, 비네팅·배경 결계 문양(SVG) 발광을
  CSS 변수로 강도 연동.
- **SEAL 연출**: 불꽃이 결계 문양 안으로 빨려들며 수축 → 문양이 봉인 완료로 빛남
  → 정적.
- 60fps 목표. `requestAnimationFrame` 단일 루프에서 오디오 상태를 읽어 시각·판정
  갱신.

## 6. 파일 구조 & 기술

단일 HTML(A안) 원칙을 지키되, 개발 중 가독성을 위해 모듈을 명확히 분리한다.

```
index.html          # 진입점
  ├─ audio.js       # AudioEngine: 오실레이터·게인·beat 계산·resume
  ├─ state.js       # 상태머신 ATTRACT/PLAY/SEAL + 타이머·리셋
  ├─ fire.js        # 캔버스 파티클 도깨비불 렌더러
  ├─ ui.js          # 슬라이더·게이지·문구·화면 이펙트
  └─ main.js        # rAF 루프: distress 계산 → 각 모듈에 반영
manifest.json       # 홈화면 전체화면 실행(landscape, standalone)
```

- 배포 시 단일 파일로 합칠 수 있으나 개발 중엔 모듈별 단일 책임으로 분리.
- 각 모듈은 인터페이스로만 소통: 예 `audioEngine.getBeat()`,
  `fire.setDistress(x)`, `state.transition(event)`.
- **외부 의존성 0** → 오프라인 보장.

## 7. 검증 방법

판정 로직과 연출을 분리해 테스트한다.

- **순수 함수 단위 테스트** (오디오/DOM 없이 검증):
  - `computeBeat(f1, f2)` → |f1−f2|
  - `computeDistress(beat)` → 목표 구간에서 1, 벗어나면 0으로 감소
  - 상태 전이 함수(ATTRACT→PLAY→SEAL→ATTRACT, 유휴 복귀)
  - 진행 링 채움/감소 누적 로직
- **수동 체크리스트** (아이패드 사파리 실기기):
  - 첫 터치 후 실제 두 톤·맥놀이 소리 재생
  - 슬라이더 조작 시 부드러운 주파수 변화(무클릭)
  - 목표 구간에서 도깨비불·화면·소리 distress 상승
  - 3초 유지 시 봉인 성공 연출 및 4초 후 자동 초기화
  - 20초 무입력 시 ATTRACT 복귀
  - 가로 전체화면·홈화면 실행 확인

## 9. 범위 밖 (YAGNI)

- 리깅된 도깨비 캐릭터 애니메이션(표정/자세) — 아트 부담으로 제외.
- 점수·레벨·랭킹 시스템 — 목표→봉인→리셋 단일 루프로 충분.
- 다국어/설정 화면·관리자 UI — 전시 단일 목적.
- 서비스워커 캐싱(정식 PWA) — 파일 교체 운영을 방해할 수 있어 제외, 매니페스트만.
- 2인 협력 모드 — 1인 양손 기준.
